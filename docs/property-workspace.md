# Карточка объекта

В `core/property_detail.py` функция `editable_sections()` задаёт поля, которые можно менять в каждом разделе, и применимость по типу объекта. Настройка подписей и единиц находится там же. Шаблоны `property_section.html` и `property_section_form.html` строят список значений и форму на основе этой конфигурации. Выборы и виджеты берутся из существующей модели `Property`. Общие правила для карточки и полного редактора находятся в `core/property_validation.py`.

При добавлении поля проверьте его применимость, допустимые значения, связи с другими полями и текущий XML. Если значения участвуют в одном правиле, включайте их в один раздел либо учитывайте в его версии для проверки конфликтов. Тип сделки, категория, подтипы, загрузка и сортировка фото остаются задачами полного редактора. Настройки выгрузок меняются прежними средствами.

Карточка отправляет HTML-форму с CSRF и непрозрачной версией раздела. Форма проверяет изменённые значения модели. Условный SQL UPDATE проверяет версию по исходным значениям полей и записывает только согласованные изменения. При конфликте карточка показывает актуальные значения и предлагает открыть форму снова. Эта проверка защищает сохранения из карточки. Существующий полный редактор использует свой прежний порядок сохранения.

Если появится авторизованный API, он может использовать те же правила выбора полей, валидацию и условное сохранение. Для юридических сведений, документов, заметок и Google Drive потребуются отдельные решения по доступу, хранению и интеграции.
