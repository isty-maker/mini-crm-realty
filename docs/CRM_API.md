# CRM API v1

API работает только по HTTPS при включённом `CRM_REQUIRE_STAFF_LOGIN`. Используйте `Authorization: Bearer <ключ>`. Сессия браузера и параметры URL не дают доступа. Ключ привязан к активному сотруднику и имеет права чтения либо чтения и записи. Ответы имеют `Cache-Control: no-store`. При отключении сотрудника через `crm_invite --disable` или сохранении отключённой учётной записи ключи отзываются. Повторная активация их не восстанавливает. Смена пароля или серверного ключа также требует перевыпуска. Не отключайте сотрудников массовым SQL или QuerySet.update, эти операции обходят штатный отзыв.

Из закрытой операторской консоли `python manage.py crm_api_key <сотрудник> --label <имя>` выдаёт ключ чтения. Добавьте `--write` для записи и `--identifiers` только для клиента, которому нужны кадастровый номер и номер квартиры. Старые ключи, выданные до миграции прав, требуют перевыпуска. Ключ показывается один раз. `--revoke <id>` отзывает ключ, а `--rotate <id>` атомарно выдаёт новый с прежними правами. Секреты не передавайте через общий терминал, командную строку в истории, тикеты или логи. Храните ключ в секретном хранилище клиента. Webhook, SQL, публикация, расходы и удаление не входят в v1.

## Маршруты

| Метод и путь | Запрос и результат |
|---|---|
| GET /api/v1/objects/ | `q`, `status`, `page`, `page_size` (1–100). Возвращает `items[{id,address,status}]`, страницу, размер и количество. |
| GET /api/v1/objects/{id}/ | `id`, `version`, `listing`, `workspace`, `collections`. Версия также в `ETag`. |
| POST /api/v1/objects/ | `{"listing":{...}}`. Новый черновик, обе выгрузки выключены. Требует `Idempotency-Key`. Совпадение кадастрового номера либо адреса и номера квартиры при той же операции возвращает 409. При неполной идентификации или неоднозначном совпадении dry-run показывает предупреждение, после сверки создание можно подтвердить через `confirm_possible_duplicate: true`. |
| PATCH /api/v1/objects/{id}/ | `{"listing":{...},"workspace":{"status":{...},"terms":{...},"legal":{...}}}`. Любые группы могут отсутствовать. Требует `If-Match` из GET. Изменение нескольких групп атомарно. |
| GET /api/v1/objects/{id}/{collection}/ | Список связанных записей и версия объекта. |
| POST /api/v1/objects/{id}/{collection}/ | Создаёт одну запись. Тело — поля записи. Требует `Idempotency-Key` и версию объекта в `If-Match`. |
| GET /api/v1/objects/{id}/{collection}/{record_id}/ | Читает одну связанную запись с её собственной версией. |
| PATCH /api/v1/objects/{id}/{collection}/{record_id}/ | Меняет переданные поля записи. Тело `{"retire":true}` отдельно помечает запись неактуальной без удаления. Требует её версию. |
| GET /api/v1/objects/{id}/changes/ | Последние 100 событий с автором, временем, источником и именами изменённых полей. `diff` содержит только переходы разрешённых перечислений и пометку актуальности. |
| GET /api/v1/document-types/ | Справочник `{id,slug,title}` для поля `document_type`. |

`HEAD` поддерживается на маршрутах чтения. Запись коллекции содержит `is_current`. GET сохраняет доступ к помеченным записям для сверки. Изменение помеченной записи возвращает 409. Актуальная ссылка из документа защищает файл от пометки. Коллекции `files`, `documents`, `bases`, `owners` и `notes` изменяются по стабильным ID. Пропуск коллекции или поля ничего не удаляет. Ссылку оригинала сначала сохраните в `files`, затем передайте ID файла в `documents.original`. Связи с другим объектом запрещены. ID автора и даты создания заметки вычисляются сервером.

### Поля, типы и перечисления

Канонический разрешённый список публичных полей находится в [`LISTING_FIELDS`](../crm_api/records.py). Категория, операция и поля подтипов разрешены при создании. Основные типы: `flat`, `room`, `house`, `land`, `commercial`, `garage`. Операции: `sale`, `rent_long`, `rent_daily`. Валюты: `rur`, `usd`, `eur`. Состояние, архив и флаги выгрузки видны в ответе и запрещены для записи. Площадь и цена передаются десятичными строками, например `"60.25"`. Счётчики и ID — JSON integer. Булевы поля — `true` или `false`. Дата — `YYYY-MM-DD`, дата и время — ISO 8601. `null` допустим только у nullable-полей модели, пустая строка — у необязательного текста.

Ключ с дополнительным правом видит и может передавать `cadastral_number` (четыре группы цифр через двоеточие) и `flat_number` (строка до 32 символов). Пустая строка очищает значение, пропущенное поле сохраняется. Номер не извлекается из адреса. Для чужого ключа эти поля скрыты даже в ответе о конфликте. Правила текущих публичных XML сохраняются. При включённой выгрузке уже действующие теги `CadastralNumber` и `Apartment` могут раскрывать заполненные значения. Перед массовым заполнением включённых объектов согласуйте это с владельцем. Если значения должны оставаться приватными, изменение контракта XML требует отдельного решения. Разные номера квартир одного здания допустимы. Неоднозначные совпадения между разными операциями требуют сверки, автоматически объекты не объединяются.

Канонический список рабочих и связанных полей находится в [`SCOPES`](../core/private_records.py). Коды сохраняемых перечислений определены в [моделях](../core/workspace_models.py). Рабочий статус: `unknown`, `preparing`, `active`, `paused`, `deposit`, `closing`, `sold`, `let`, `renewal`, `expired`, `terminated`. Документ: применимость `unknown`, `not_needed`, `required`; наличие `unknown`, `missing`, `present`; проверка `unknown`, `checked`, `issues`. При проверке документа укажите `checked_on`. Отсутствующий документ не может быть помечен проверенным или иметь привязанный оригинал. Допустимо зафиксировать замечание о безуспешном поиске с датой. Основания: `unknown`, `purchase`, `inheritance`, `gift`, `privatization`, `participation`, `other`. Владельцы имеют `name`, `share_numerator` и `share_denominator`. Заметка принимает только `text`. Публикация не меняется при изменении рабочего статуса.

### Версии, предпросмотр и повтор

Передайте `?dry_run=1` с телом POST или PATCH, чтобы получить старое и предлагаемое значение и предупреждения без записи. Для PATCH и связанных записей возвращается версия снимка. При сохранении используйте её в `If-Match: "<версия>"`, включая кавычки. При 409 прочитайте объект и подтвердите изменения заново. У POST создания объекта версии ещё нет, его защищают проверка идентичности и ключ идемпотентности. Повтор с тем же ключом и тем же JSON возвращает тот же ID и `Idempotency-Replayed: true`; тело показывает текущее состояние. Ключ действует в пределах API-ключа и маршрута. Другое тело с тем же ключом возвращает 409.

Ошибки имеют форму `{"error":{"code":"…","message":"…","fields":…}}`. Успехи: 200 и 201. Ошибки: 400 запрос, 401 ключ, 403 доступ или HTTPS, 404 запись, 405 метод, 409 конфликт или возможный дубль, 413 размер, 415 тип содержимого, 422 поля, 428 нет версии. Ответ конфликта содержит текущие данные и версию там, где их можно повторно получить после перепроверки.

## Пример

Используйте переменную из закрытого хранилища. Ниже ключ и хост вымышлены.

```bash
crm_url='https://example.invalid/api/v1/objects/'
crm_token='synthetic-example-not-a-real-key'
curl -sS -H "Authorization: Bearer $crm_token" "$crm_url"
curl -sS -X POST -H "Authorization: Bearer $crm_token" \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: demo-import-1' \
  --data '{"listing":{"address":"Учебный объект","flat_number":"Тест-7","category":"flat","operation":"sale","flat_type":"apartment","total_area":"60.25","currency":"rur"}}' \
  "$crm_url"
curl -si -H "Authorization: Bearer $crm_token" "${crm_url}1/"
curl -sS -X PATCH -H "Authorization: Bearer $crm_token" \
  -H 'Content-Type: application/json' --data '{"listing":{"price":"6350000.25"}}' \
  "${crm_url}1/?dry_run=1"
```

После dry-run повторите PATCH без параметра и с заголовком `If-Match`, затем повторите GET и проверьте карточку. [Синтетический паспорт](examples/crm-api-passport.json) разложен на создание, общую правку и массивы связанных записей. Воспроизводимый тест `python manage.py test crm_api.tests.test_api` преобразует `documents[].type` в ID справочника, а `documents[].file` в ID ранее созданного файла. Тест проводит dry-run, запись, повтор, сравнение с карточкой, конфликт ручной правки и проверки обоих XML.


### Репетиция на локальной HTTPS-копии

На новой синтетической БД выпустите временный тестовый ключ с `--write --identifiers`, задайте его через `CRM_TEST_API_TOKEN` вне истории команд и импортируйте цепочку по одной записи. У сертификата локального сервера должен быть SAN для выбранного имени или адреса.

```bash
python scripts/rehearse_crm_passport.py --origin https://localhost:9443 --ca-file /path/to/test-ca.pem --create
python scripts/rehearse_crm_passport.py --origin https://localhost:9443 --ca-file /path/to/test-ca.pem --create --apply
python scripts/rehearse_crm_passport.py --origin https://localhost:9443 --ca-file /path/to/test-ca.pem --object-id 1
```

Для повторной актуализации добавьте `--apply --expected-etag '"<версия>"'` из предыдущего чтения. Скрипт проверяет ответ повторным GET. Корневой dry-run на новой базе проверяет черновик. Предпросмотр связанных записей начинается после создания тестового объекта. Каждый POST коллекции транзакционен отдельно, поэтому для ручного восстановления после прерывания сохраните ID и сверяйте уже созданные записи. Повторный запуск полного примера делайте на свежей временной базе, для существующего объекта используйте режим актуализации. Фото остаются на отдельном HTML-маршруте. Drive и Авито не подключены. Массовое заполнение пока выполняется последовательными операциями.
